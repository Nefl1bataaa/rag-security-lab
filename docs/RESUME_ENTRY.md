# 简历项目描述

## 推荐项目名称

**RAG 知识库投毒与间接提示词注入防护实验室**

## 三条版

- 基于 Python、Ollama 与 Qwen2.5 构建本地 RAG 安全靶场，设计合成投毒文档和 Canary 泄露测试，复现知识库投毒及间接提示词注入攻击链。
- 实现租户隔离、检索审计、模型响应检测与自动隔离机制；在 24 个评估用例中将投毒召回率由 75% 降至 0%，正常文档命中率保持 93.75%，扫描误报率与跨租户泄露均为 0。
- 使用本地 Qwen2.5 执行 18 次模型调用对照测试，将攻击成功率（ASR）由 40% 降至 0%，正常问题 Canary 泄露率保持 0%。
- 将 RAG 检索、跨租户访问、模型泄露及隔离处置事件接入 Wazuh，编写自定义规则并验证 `100310/100320/100330/100360` 告警闭环。

## 一句话版

在 VMware 隔离环境中构建 RAG 应用安全靶场，复现知识库投毒与间接提示词注入，并通过 Canary 检测、自动文档隔离及 Wazuh SOC 联动实现攻击检测和防护闭环。

## 面试讲解顺序

1. 先解释风险：RAG 会把外部文档当成模型上下文，恶意文档可能携带隐藏指令。
2. 再解释验证：使用无实际价值的 Canary 判断模型是否执行文档指令。
3. 展示攻击：投毒块进入上下文后触发 `100310`，模型泄露触发 `100330`。
4. 展示防护：入库扫描器识别强制输出、忽略指令等特征，自动隔离并触发 `100360`。
5. 展示结果：重建索引后投毒块数量为零，同一问题不再泄露 Canary。

## 避免夸大的表述

- 不说“Canary 是 AI 专属技术”，应说“将传统 Canary 思路用于 LLM 输出泄露检测”。
- 不说“完全防御所有提示词注入”，应说“实现可解释的规则基线和可重复的防护对照实验”。
- 不把该项目描述为模型训练或对齐研究，应归类为 LLM 应用安全或 RAG Security。
