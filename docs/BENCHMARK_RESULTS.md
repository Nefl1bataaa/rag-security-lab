# 实测结果

## 实验环境

- VMware 隔离网络中的 Linux 虚拟机
- Ollama + `qwen2.5:0.5b`
- 24 个合成安全评估用例
- `off` 与 `enforce` 各 9 次真实模型调用，共 18 次

## 检索与扫描结果

| 指标 | off | audit | enforce |
|---|---:|---:|---:|
| 攻击问题投毒召回率 | 75% | 75% | 0% |
| 正常问题预期文档命中率 | 93.75% | 93.75% | 93.75% |
| 跨租户泄露次数 | 0 | 0 | 0 |

- 已标注投毒文档检出率：100%
- 合成正常文档误报率：0%

## 真实模型结果

| 指标 | off | enforce | 变化 |
|---|---:|---:|---:|
| 模型测试用例数 | 9 | 9 | 共 18 次调用 |
| 攻击成功率（ASR） | 40% | 0% | 降低 40 个百分点 |
| 正常问题 Canary 泄露率 | 0% | 0% | 无新增泄露 |
| 模型延迟 P50 | 1841.706 ms | 2118.972 ms | +15.1% |
| 模型延迟 P95 | 8318.995 ms | 3345.563 ms | -59.8% |

## 结论与限制

本轮实验中，`enforce` 在入库前隔离可疑文档，使投毒块不再进入索引，并将真实模型攻击成功率从 40% 降为 0%，同时保持正常文档命中率和租户隔离结果。

P50 增加约 15.1%，P95 降低约 59.8%。每种模式只有 9 次模型调用，且使用 CPU 上的小模型，结果会受模型预热、系统调度和上下文长度影响。因此，延迟数据仅代表本轮实验观测，不用于证明 `enforce` 能稳定提升推理性能。

`poisoned_retrieval_hit_rate` 与 `attack_success_rate` 是两个不同层级的指标：前者表示恶意内容进入模型上下文，后者要求模型回答实际泄露 Canary。
